# Сервер сквоков Galaxy ATM System

Один сервер на всех: хранит, какие коды выданы каким бортам, выдаёт свободный код по
запросу плагина и освобождает его, только когда пилот ушёл из сети VATSIM.

## Что внутри

| Путь | Что это |
|---|---|
| `schema.sql` | Таблицы MySQL (импортируется один раз) |
| `config.sample.php` | Пример настроек — на сервере копируется в `config.php` (не в git) |
| `lib/` | Общий код (БД, выбор кода, чтение данных VATSIM) |
| `cron/vatsim_sync.php` | Задача раз в минуту: данные VATSIM, освобождение кодов |
| `public/api/assign.php` | `POST` — выдать код борту |
| `public/api/report.php` | `POST` — код, введённый диспетчером вручную |
| `public/api/state.php` | `GET` — все занятые коды |
| `public/api/name.php` | `GET` — имя диспетчера для блока «Пользователь» (см. «Имена диспетчеров») |
| `public/api/health.php` | `GET` — проверка, что всё живо (без ключа) |
| `public/api/login.php` | `POST` — вход в панель по ФИО и паролю (см. «Регистрация и вход») |
| `public/register/index.php` | Страница регистрации в системе КСА: CID, ФИО, пароль; под `?reset` — заявка на сброс пароля |
| `public/admin/index.php` | АРМ инженера системы: заявки на сброс, исправить имя, сбросить пароль, удалить диспетчера (см. «Админ-страница») |
| `deploy.sh` | Раскладывает `public/` и `lib/` в папку сайта — см. «Установка», шаг 6 |

Наружу смотрит только `public/`; `lib`, `cron` и `config.php` из интернета недоступны.

## Как сервер отличает своих

**У плагина нет никакого ключа.** Все секреты сервиса лежат только в `config.php`
на сервере и никуда оттуда не уезжают — ни в `GalaxyATMSystem.json`, ни в
отдельный файл рядом с плагином, ни в чат.

Вместо ключа сервер проверяет то, чего не подделать конфигом: **диспетчер прямо
сейчас сидит на этой позиции в сети VATSIM.** В каждом запросе плагин называет
свой позывной контроллера (`ULLI_GND`, `ULLL_APP`, …); сервер сверяет его со
списком контроллеров из фида VATSIM, который и так качает раз в минуту, и
выдаёт коды только тому, кто в этом списке есть. Наблюдатели (OBS) в список не
попадают: они записываются отдельно (`network_observers`), и по ним сервер
отвечает только на `api/name.php` — открыть панель плагина наблюдатель может,
выдавать коды нет. CID из фида записывается рядом с каждым выданным кодом, так
что видно, кто его взял.

Что это даёт и чего не даёт:

- конфиг плагина можно спокойно выкладывать куда угодно — в нём нечего украсть;
- новому диспетчеру ничего не надо передавать: подключился к сети — коды пошли;
- подделать запрос может тот, кто знает адрес сервера и видит, что позиция сейчас
  онлайн. Максимум вреда — занять коды из наших диапазонов; это видно в
  `assignments` вместе с позывным и CID. Общий ключ на всех от этого защищал не
  лучше: он лежал файлом на каждом компьютере и утекал с первой же пересылкой.

Если сервис всё-таки нужно закрыть совсем — в `config.php` есть необязательный
`api_key`: пока он не пустой, плагин обязан слать его в заголовке `X-Api-Key`
**вдобавок** к проверке онлайна, и тогда ключ снова придётся раздавать всем (см.
шаг 10). По умолчанию он пустой.

## Установка на Beget (один раз)

Сайт, который уже есть на аккаунте, не затрагивается: сервис ставится **отдельным
сайтом** на поддомен, а файлы берутся прямо из репозитория на GitHub.

В примерах ниже:

- `ЛОГИН` — логин от панели Beget;
- `СЕРВЕР` — имя сервера из панели (вида `имя.beget.tech`, см. шаг 3);
- `ДОМЕН` — адрес, по которому открывается сайт. Если у вас нет своего
  зарегистрированного домена, Beget даёт технический `ЛОГИН.beget.tech` — тогда
  адрес сайта будет `squawk.ЛОГИН.beget.tech`, и это тоже нормально, просто без
  SSL (см. шаг 2);
- названия пунктов меню панели могут чуть отличаться — ищите по смыслу.

### Важно: где физически лежит сайт

Когда поддомен привязывается не к «сайту», созданному через «Сайты», а как
самостоятельный пункт в «Управлении доменами и поддоменами», Beget заводит для
него **отдельную папку в домашнем каталоге, названную точно как сам поддомен** —
например `~/squawk.ЛОГИН.beget.tech/public_html` — а вовсе не
`~/squawk/public_html`, куда могло бы казаться логичным положить файлы. Это и
есть настоящий корень сайта; в шаге 6 мы проверяем, какая папка используется
на самом деле, командой `ls -la ~`.

Итог после всех шагов:

```
~/squawk/repo/                        ← клон репозитория с GitHub (весь код и история)
└── server/
    ├── config.php                    ← создаёте вы (шаг 7), в git не попадает
    ├── lib/  cron/  public/ ...

~/ИМЯ_КОРНЯ_САЙТА/                    ← папка, которую реально показывает веб-сервер
├── public_html/                      ← копия server/public (не ссылка — см. шаг 6)
├── lib/                              ← копия server/lib
└── config.php                        ← вторая копия того же файла, что в repo/server/
```

Два `config.php` — не ошибка: тот, что в `repo/server/`, читает cron (он всегда
берёт код прямо из репозитория), а тот, что в корне сайта, читает веб-сервер.
Оба создаются один раз и меняются вместе, только если когда-нибудь понадобится
сменить пароль базы или ключ API.

### Шаг 1. Сайт и поддомен

1. Панель → **«Сайты»** → создать новый сайт. Имя папки: `squawk`.
2. Панель → **«Управление доменами и поддоменами»** → вкладка **«Поддомены»** →
   создать поддомен `squawk` для вашего домена (или для технического
   `ЛОГИН.beget.tech`, если своего домена нет) и привязать его к сайту `squawk`.
3. Проверка: через несколько минут `http://squawk.ДОМЕН` открывается — пусть даже
   заглушкой Beget или ошибкой 404, главное, что сервер вообще отвечает.

### Шаг 2. SSL (https) — если есть свой домен

1. Панель → **«SSL сертификаты»** → выпустить **бесплатный** сертификат для
   `squawk.ДОМЕН`.
2. Если Beget пишет, что домен не найден или не указывает на сервер — подождите
   15–30 минут после шага 1 (поддомен ещё расходится по DNS) и повторите.
3. Проверка: `https://squawk.ДОМЕН` открывается с замком в браузере.

Если сертификат выпустить не удаётся (например, нет своего зарегистрированного
домена — только технический `ЛОГИН.beget.tech`) — не страшно, дальше везде
используйте `http://` вместо `https://`. Секретов в запросах нет (см. «Как
сервер отличает своих»), так что перехватывать нечего, но при появлении своего
домена к этому шагу стоит вернуться.

### Шаг 3. Версия PHP

1. Панель → «Сайты и прилинкованные домены» → у строки **именно вашего поддомена**
   `squawk.ДОМЕН` (не у `squawk`, не у основного домена — у записей могут быть
   разные настройки) → шестерёнка → версия PHP **8.1 или новее** (лучше самая
   новая 8.x). Режим CGI — выключен.
2. Запомните выбранную версию, например `8.2` — она понадобится в шагах 6 и 8.

### Шаг 4. База данных

1. Панель → **«MySQL»** → создать базу. Beget создаст пользователя с тем же именем,
   что и база (вида `ЛОГИН_squawk`), и попросит задать пароль. **Запишите оба.**
   Хост базы — `localhost`.
2. В списке баз у новой базы нажмите вход в **phpMyAdmin**.
3. В phpMyAdmin слева выберите базу → сверху вкладка **«Импорт»** → «Выберите файл» →
   `server/schema.sql` из репозитория (на компьютере: `C:\Galaxy ATM System\server\schema.sql`)
   → **«Вперёд»** / «Импорт» внизу страницы.

   Если импорт через phpMyAdmin не пройдёт — тот же файл можно накатить прямо по
   SSH (после шага 5):
   ```bash
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk < ~/squawk/repo/server/schema.sql
   ```
   Команда ничего не выводит при успехе — это нормально.
4. Проверка:
   ```bash
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk -e "SHOW TABLES"
   ```
   Должны быть `assignments`, `network_pilots`, `network_controllers`,
   `user_names`, `rate_limit`, `sync_state`.

### Шаг 5. SSH — подключение к серверу

1. Панель → главная страница → в меню слева **включить SSH**.
2. Там же, в блоке **«Тех. информация»**, найдите **имя сервера** — это `СЕРВЕР`
   (вида `имя.beget.tech`).
3. На компьютере откройте **PowerShell** (Пуск → PowerShell; SSH в Windows 10/11 уже
   встроен) и подключитесь:
   ```
   ssh ЛОГИН@СЕРВЕР
   ```
   - На вопрос `Are you sure you want to continue connecting (yes/no)?` введите `yes`.
   - Введите пароль от панели Beget. **При вводе пароля на экране ничего не
     отображается** — это нормально, просто наберите и нажмите Enter.

   > **Если пароль не подходит** (`Permission denied`), убедитесь, что раскладка
   > английская и Caps Lock выключен, и что это именно пароль от панели Beget, а не
   > от FTP или от MySQL. Не помогло — в панели раздел **«SSH доступ»** умеет сам
   > сгенерировать пару ключей кнопкой **«Создать ключ»** и сразу разрешить по ней
   > вход, без пароля вообще; используйте эту пару с `ssh -i путь_к_приватному_ключу
   > ЛОГИН@СЕРВЕР`.
4. Проверка: появилось приглашение командной строки Beget. Выполните:
   ```bash
   git --version
   ls /usr/local/bin/php*
   ```
   Первая команда покажет версию git, вторая — доступные версии PHP (среди них должна
   быть та, что выбрана в шаге 3, например `/usr/local/bin/php8.2`).

   > Если `git` пишет `command not found`, выполните `ssh localhost -p222` — это
   > окружение Beget с дополнительными программами — и продолжайте там.

Все команды следующих шагов вводятся **в этом окне SSH**. Каждую команду можно
скопировать и вставить (в PowerShell вставка — правой кнопкой мыши).

### Шаг 6. Скачать репозиторий и разложить файлы по папке сайта

Репозиторий на GitHub публичный, поэтому отдельный ключ для чтения не нужен —
клонируется обычной HTTPS-ссылкой:

```bash
git clone https://github.com/Yurko-v/ATM-Galaktika-ULLL.git ~/squawk/repo
```

Дальше нужно найти папку, которую **реально** показывает веб-сервер для вашего
поддомена (см. врезку выше «Где физически лежит сайт») — она не обязательно
`~/squawk`:

```bash
ls -la ~
```

Среди строк найдите папку с именем как у поддомена целиком, например
`squawk.ЛОГИН.beget.tech` (в общем случае — `squawk.ДОМЕН`). Дальше в примерах
это `~/ИМЯ_КОРНЯ_САЙТА` — подставляйте свою.

**Символическую ссылку сюда класть не надо** — на части аккаунтов Beget веб-сервер
отказывается идти по ссылке за пределы папки сайта, и любой запрос отвечает
ошибкой 500 (мы это проверили: даже пустой `<?php phpinfo();` через ссылку не
открывался). Вместо ссылки — обычное копирование, шаблонным скриптом из
репозитория:

```bash
sh ~/squawk/repo/server/deploy.sh ~/squawk/repo/server ~/ИМЯ_КОРНЯ_САЙТА
ls -la ~/ИМЯ_КОРНЯ_САЙТА
```

Должны появиться папки `public_html` (с подпапкой `api`) и `lib`. Этот же скрипт
и будет запускать автодеплой при каждом обновлении с GitHub — см. раздел ниже.

### Шаг 7. Настройки сервера (config.php) — в двух местах

Один и тот же файл нужен и репозиторию (его читает cron), и папке сайта (её читает
веб-сервер) — см. врезку выше.

Заполнять надо только доступ к базе: ключ API больше не нужен — кто свой,
сервер определяет по сети VATSIM (см. «Как сервер отличает своих»).

1. Создать `config.php` из примера и сразу вписать в него данные базы (шаг 4),
   одной командой (замените `ИМЯ_БАЗЫ`, `ПОЛЬЗОВАТЕЛЬ_БАЗЫ`, `ПАРОЛЬ_БАЗЫ` на
   свои значения перед тем, как нажать Enter):
   ```bash
   cp ~/squawk/repo/server/config.sample.php ~/squawk/repo/server/config.php
   sed -i \
     -e "s/dbname=CHANGE_ME/dbname=ИМЯ_БАЗЫ/" \
     -e "s/'user' => 'CHANGE_ME'/'user' => 'ПОЛЬЗОВАТЕЛЬ_БАЗЫ'/" \
     -e "s/'pass' => 'CHANGE_ME'/'pass' => 'ПАРОЛЬ_БАЗЫ'/" \
     ~/squawk/repo/server/config.php
   ```
   Имя пользователя базы на Beget обычно совпадает с именем самой базы (то, что
   вы видели в панели рядом с базой в шаге 4) — не с логином панели.
2. Проверка, что подставилось верно (нигде не должно остаться `CHANGE_ME`):
   ```bash
   cat ~/squawk/repo/server/config.php
   ```
3. Скопировать этот же файл в папку сайта — именно его читает веб-сервер:
   ```bash
   cp ~/squawk/repo/server/config.php ~/ИМЯ_КОРНЯ_САЙТА/config.php
   ```
4. Проверка — открыть в браузере `http://squawk.ДОМЕН/api/health.php` (или
   `https://`, если в шаге 2 получилось). Должно быть:
   ```json
   {"ok":true,"network_updated":null,"network_fresh":false,
    "controllers_updated":null,"controllers_fresh":false,"controllers_online":0,
    "api_key":false,"active":0}
   ```
   - `network_fresh: false` и `controllers_fresh: false` пока нормально — данные
     VATSIM появятся после шага 8;
   - `api_key: false` — так и должно быть: плагину ключ не нужен;
   - `{"error":"server_error"}` — неверные данные базы в одном из двух `config.php`.
   - `HTTP ERROR 500` на *любом* PHP-файле, даже на пустом — значит, шаг 6 сделан не
     до конца (файлы не скопированы в правильную папку, либо это снова ссылка).
   - `Not Found` (страница Apache, а не JSON) — сайт смотрит не в ту папку; сверьте
     `ИМЯ_КОРНЯ_САЙТА` с тем, что показал `ls -la ~` в шаге 6.

`config.php` в обеих папках — в `.gitignore`: git их не видит и не трогает, а
`deploy.sh` (в том числе автодеплой) их не перезаписывает.

### Шаг 8. Синхронизация с VATSIM (cron)

1. Сначала запустить задачу вручную (подставьте свою версию PHP из шага 3):
   ```bash
   /usr/local/bin/php8.2 ~/squawk/repo/server/cron/vatsim_sync.php
   ```
   Правильный ответ — строка вида:
   ```
   2026-09-11 18:30:00 vatsim_sync: pilots=1234 controllers=56 held=0 released=0
   ```
   Если ошибка — пришлите её текст.
2. Панель → **«CronTab»** → вкладка **«Составить задание вручную»**:
   - время: **каждую минуту** (`*/1 * * * *`);
   - команда (та же, что проверили, плюс запись в лог):
     ```
     /usr/local/bin/php8.2 ~/squawk/repo/server/cron/vatsim_sync.php >> ~/squawk/cron.log 2>&1
     ```
   - **Добавить задание**.
3. Проверка через 2–3 минуты:
   - `http://squawk.ДОМЕН/api/health.php` → `"network_fresh": true` и
     `"controllers_fresh": true` (без второго сервер никого не пустит);
   - на Beget `tail ~/squawk/cron.log` → по строке `pilots=...` на каждую минуту.

### Шаг 9. Проверить выдачу кодов

Сервер выдаёт коды только позициям, которые сейчас онлайн в сети VATSIM, — а из
командной строки вы не онлайн. Поэтому для проверки надо на время разрешить
пару выдуманных позывных: в **обоих** `config.php` (репозитория и папки сайта)
заменить строку `'test_positions' => [],` на

```php
'test_positions' => ['ULLI_DEL', 'ULLL_APP'],
```

Дальше команды можно выполнять прямо на Beget в окне SSH (подставьте домен):

```bash
URL=http://squawk.ДОМЕН/api

# выдать код тестовому борту
curl -s -X POST $URL/assign.php -H "Content-Type: application/json" \
     -d '{"callsign":"TEST1","position":"ULLI_DEL"}'

# с другой позиции тот же борт -> тот же код, "existing":true
curl -s -X POST $URL/assign.php -H "Content-Type: application/json" \
     -d '{"callsign":"TEST1","position":"ULLL_APP"}'

# новый код тому же борту
curl -s -X POST $URL/assign.php -H "Content-Type: application/json" \
     -d '{"callsign":"TEST1","position":"ULLL_APP","new":true}'

# все выданные коды
curl -s "$URL/state.php?position=ULLI_DEL"
```

- `{"error":"not_online"}` — позывной не в `test_positions` и не сидит на сети;
  так и должно отвечать всем посторонним.
- `{"error":"network_stale"}` — сервер не видит свежих данных VATSIM: не сделан
  шаг 8, или cron перестал ходить. Пока это так, коды не выдаются никому.
- `TEST1` в сети VATSIM нет, поэтому примерно через 10 минут cron сам освободит его
  код и он пропадёт из `state.php` — так заодно проверяется освобождение.

**Закончив проверку, верните `'test_positions' => [],` в обоих `config.php`** —
перечисленным там позывным сервер верит на слово.

### Шаг 10. Подключить плагин

У каждого диспетчера в `Documents\Galaxy ATM System\GalaxyATMSystem.json`:

```json
"Squawk": {
  "Enabled": true,
  "ServerUrl": "http://squawk.ДОМЕН/api",
  "PollSeconds": 15,
  "AllowSweatbox": false,
  "Debug": false
},
```

(`https://`, если в шаге 2 получилось выпустить сертификат.)

**Больше ничего передавать диспетчеру не надо** — ни ключа, ни файла рядом с
плагином. Этот кусок конфига одинаков у всех и не содержит ничего секретного,
так что его можно просто скинуть в чат. Коды пойдут, как только человек
подключится к сети как диспетчер; первую минуту после подключения сервер может
ответить «не вижу вас онлайн» — это нормально, он сам переспросит VATSIM.

Ключ нужен только в одном случае: если в `config.php` на сервере заполнен
необязательный `api_key`. Тогда каждому диспетчеру дополнительно кладётся файл
`Documents\Galaxy ATM System\squawk-key.txt` с ключом одной строкой, а в конфиг
добавляется `"ApiKeyFile": "squawk-key.txt",`. Файл с ключом внесён в
`.gitignore`. По умолчанию `api_key` пустой и всё это не нужно.

Остальные два ключа:
- **`AllowSweatbox`** — разрешить выдачу кодов на тренировке. По умолчанию выключено:
  sweatbox тратит тот же боевой пул. Включайте только на время проверок.
- **`Debug`** — писать в канал «ULLL Squawk» по строке на каждый шаг клика (какая
  функция пришла, что ответил сервер, что проставилось). Для разбора, когда клик
  «ничего не делает».

Затем в EuroScope команда `.reload` (или перезапуск) и колонка «ULLL Squawk» в
Departure list.

## Имена диспетчеров

В блоке «Пользователь» плагин пишет диспетчера как `Фамилия И.О.`. Сам он берёт
имя из сети VATSIM латиницей и переводит на русский — и иногда ошибается
(`Velbovets` → `Велбоветс`), а отчества в сети нет вовсе. Правильное имя
вписывается один раз в таблицу `user_names` на сервере, и дальше его видит
плагин у этого диспетчера на любом компьютере.

Плагин читает из таблицы только своё имя: сервер ищет запись по CID, который
VATSIM показывает для позиции, где диспетчер сейчас сидит.

### Регистрация и вход

1. Диспетчер открывает `http://<адрес сайта>/register/` и вводит CID на VATSIM,
   фамилию, имя, отчество (если есть) и придумывает пароль (не короче 8
   символов). Сайт отвечает «Вы успешно зарегистрированы в системе КСА» и
   записывает строку в `user_names`: имя для блока «Пользователь», отдельно
   фамилию, имя и отчество, и хэш пароля (сам пароль нигде не хранится).
2. В EuroScope, подключившись к VATSIM, диспетчер нажимает **LOGIN**. Открывается
   окно «Вход в систему КСА»: фамилия, имя, отчество, пароль. Пароль при вводе
   скрыт. Enter — следующее поле, на пароле — вход.
3. Плагин отправляет их `POST`-запросом в `api/login.php`. Сервер берёт CID не из
   запроса, а из сети VATSIM — тот, под которым диспетчер сидит на позиции, — и
   сверяет ФИО (без учёта регистра и ё/е) и пароль с регистрацией этого CID.
   Совпало — панель открывается.

Ответы `api/login.php`: `403 not_registered` — CID не зарегистрирован на сайте
(или у записи нет пароля); `401 wrong_credentials` — неверные ФИО или пароль;
`429 rate_limited` — больше 5 попыток в минуту на один CID. Bypass после неверного
пароля не открывается, только после ошибки сервиса (нет сети, нет сервера).

**Один CID регистрируется один раз.** Повторная регистрация того же CID
отклоняется. Проверить на сайте, что CID принадлежит именно этому человеку,
нельзя (у VATSIM для этого есть только собственный вход VATSIM Connect). Но чужая
регистрация никого не пустит в панель: вход принимается только с позиции, которую
сеть показывает под этим CID. Если CID занял не тот человек или диспетчер забыл
пароль — сброс пароля открывает регистрацию заново (следующий раздел).

### Забыли пароль

Почты у системы нет, а отличить владельца CID от того, кто знает его ФИО, сайт
не может — поэтому пароль сбрасывает человек, а сайт только принимает заявку.

1. Диспетчер открывает `http://<адрес сайта>/register/?reset` («Забыли пароль?» в
   шапке страницы регистрации) и вводит CID, ФИО и, если нужно, как с ним
   связаться. Пароль при этом не меняется — заявка ложится в таблицу
   `password_resets`, по одной открытой на CID: повторная заявка обновляет ту,
   что уже ждёт. С одного адреса — не больше 3 заявок в минуту.
2. Заявка появляется первой карточкой в АРМ инженера системы: CID, ФИО из
   заявки, а если оно не совпало с записью — имя из `user_names` рядом, красным.
   Инженер сверяет, кто просит, и нажимает **«Сбросить пароль»** — пароль
   удаляется, заявка уходит из списка. **«Отклонить»** убирает только заявку,
   пароль остаётся прежним.
3. После сброса диспетчер регистрируется на сайте заново с тем же CID и сам
   задаёт новый пароль.

Заявка на CID, которого нет в `user_names`, или на запись без пароля не
принимается: регистрироваться там надо обычным порядком, сбрасывать нечего.

**Таблица — это и доступ к панели.** Без регистрации в `user_names` панель плагина
не открывается, а запись, удалённая из таблицы, закрывает её у диспетчера в
течение минуты. Так админ может забрать доступ. `UserNames` в локальном
`GalaxyATMSystem.json` меняет только то, как имя написано, доступа не даёт.

У сервиса нет SSL: пароль идёт по сети открытым текстом. Страница регистрации
просит не использовать пароль от VATSIM или почты.

### Добавить или исправить имя

phpMyAdmin → база → таблица `user_names` → вкладка **«Вставить»**:

- `cid` — CID диспетчера на VATSIM (`1234567`);
- `name` — имя по-русски: полностью `Велбовец Юрий Владимирович` или уже
  сокращённо `Велбовец Ю.В.` (плагин сократит сам; `Велбовец.Ю.В` без пробела
  и последней точки тоже приведёт к этому виду). Полностью — только в порядке
  «Фамилия Имя Отчество». Без отчества пишите сразу сокращённо, `Велбовец Ю.`:
  из двух полных слов плагин первым считает имя, и `Велбовец Юрий`
  превратится в `Юрий В.`;
- `updated_at` не трогать — проставится сам.

Или одной командой по SSH (повторный запуск для того же CID заменит имя):

```bash
mysql -u ЛОГИН_squawk -p ЛОГИН_squawk -e "INSERT INTO user_names (cid, name) VALUES ('1234567', 'Велбовец Юрий Владимирович') ON DUPLICATE KEY UPDATE name = VALUES(name)"
```

Удалить запись — вкладка «Обзор» → удалить строку; панель у диспетчера закроется
с «Доступ приостановлен».

### Админ-страница

Чтобы вести список диспетчеров, не отдавая пароль от базы, есть отдельная
страница со своими логинами: `http://<адрес сайта>/admin/`. На ней видно, кто
есть в `user_names` и кто уже зарегистрировался с паролем; можно исправить имя в
блоке «Пользователь», сбросить пароль (запись остаётся, диспетчер
регистрируется на сайте заново) или удалить запись — больше ничего в базе с неё
не достать. Имя, добавленное здесь без регистрации, в панель не пускает.

Наверху, если они есть, — **заявки на сброс пароля** с сайта: кто просит, как с
ним связаться и когда подана; в списке диспетчеров такая запись помечена
«просит сброс». Сайт ничьё право на CID не проверяет, поэтому решение за
инженером — см. «Забыли пароль» выше.

**Выдать логин:**

1. По SSH сделайте хэш пароля (сам пароль в файл не пишется). Команда ждёт
   ввода: наберите пароль и нажмите Enter — в историю команд он не попадёт:

   ```bash
   php8.2 -r 'echo password_hash(trim(fgets(STDIN)), PASSWORD_DEFAULT), PHP_EOL;'
   ```

2. Откройте `config.php` **в папке сайта** (`~/<папка сайта>/config.php`, не тот,
   что в репозитории) и добавьте логин с этим хэшем — в одинарных кавычках:

   ```php
   'admins' => [
       'ivanov' => '$2y$10$....',
   ],
   ```

3. Передайте человеку адрес, логин и пароль.

**Забрать логин** — удалите его строку из `admins` или замените хэш: открытый
вход закончится на следующем клике. Вход сам заканчивается и после двух часов
без действий; с одного адреса — не больше 5 попыток входа в минуту. Входы и
изменения пишутся в журнал ошибок сайта (строки `squawk admin:`).

У сервиса нет SSL, поэтому пароль идёт по сети открытым текстом — выдавайте
пароли, которые нигде больше не используются.

### Когда плагин видит изменение

Плагин спрашивает имя сразу при подключении к сети (и при смене позиции), а
дальше — раз в минуту, пока диспетчер в сети. Имя, вписанное или исправленное в
таблице, появится у диспетчера в течение минуты, переподключаться не нужно.

Порядок, откуда берётся имя: `UserNames` в локальном `GalaxyATMSystem.json` (если
кто-то вписал себе сам) → таблица `user_names` → перевод имени из сети VATSIM →
имя из окна подключения EuroScope.

### Установка на уже работающий сервер

1. Код — автодеплоем или вручную (`git pull` + `deploy.sh`, как в шаге 6).
2. Таблицы (`user_names`, для наблюдателей `network_observers`, для заявок на
   сброс пароля `password_resets`):
   ```bash
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk < ~/squawk/repo/server/schema.sql
   ```
   `schema.sql` создаёт только недостающие таблицы, данные не трогает.
   На базе, где `user_names` уже была до регистрации с паролем, один раз добавьте
   новые столбцы:
   ```bash
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk -e "ALTER TABLE user_names ADD COLUMN surname VARCHAR(40) NULL AFTER name, ADD COLUMN first_name VARCHAR(40) NULL AFTER surname, ADD COLUMN patronymic VARCHAR(40) NULL AFTER first_name, ADD COLUMN password_hash VARCHAR(255) NULL AFTER patronymic, ADD COLUMN registered_at DATETIME NULL AFTER password_hash"
   ```
   `Duplicate column name` — столбцы уже есть, всё в порядке.
3. Проверка: `api/health.php` показывает `"user_names": 0` (или сколько уже
   вписано). `{"error":"server_error"}` — таблица не создана.
   `"registered": null` — не выполнен `ALTER TABLE` выше: сайт регистрации и
   вход по паролю не работают.
   `"observers_online": null` — нет `network_observers`: коды и имена
   диспетчеров работают, но наблюдатель не пройдёт LOGIN; через минуту после
   импорта там будет число. Если нет `password_resets`, АРМ инженера скажет об
   этом под списком диспетчеров, а заявку на сброс сайт не примет; всё
   остальное работает.

## Переход с общего ключа на проверку по сети

Это делается один раз на уже работающем сервере — после него ключ не нужен
никому.

1. **Код на сервер.** Автодеплой (раздел ниже) разложит его сам при push в `main`;
   вручную — `cd ~/squawk/repo && git pull && sh server/deploy.sh ~/squawk/repo/server ~/ИМЯ_КОРНЯ_САЙТА`.
2. **База.** Две новые таблицы и один столбец:
   ```bash
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk < ~/squawk/repo/server/schema.sql
   mysql -u ЛОГИН_squawk -p ЛОГИН_squawk -e "ALTER TABLE assignments ADD COLUMN assigned_cid VARCHAR(12) NULL AFTER assigned_by"
   ```
   `schema.sql` создаёт только недостающее (`CREATE TABLE IF NOT EXISTS`), данные
   не трогает. Вторая команда добавляет столбец, которого в старой таблице нет;
   если она скажет `Duplicate column name`, значит он уже есть — всё в порядке.
3. **Настройки.** В **обоих** `config.php` (репозитория и папки сайта) очистить
   ключ — пока он не пустой, плагины обязаны его присылать:
   ```bash
   sed -i -E "s/'api_key' *=> *'[^']*'/'api_key' => ''/" ~/squawk/repo/server/config.php ~/ИМЯ_КОРНЯ_САЙТА/config.php
   grep api_key ~/squawk/repo/server/config.php ~/ИМЯ_КОРНЯ_САЙТА/config.php
   ```
   Остальные новые настройки (`controller_max_age_sec`, `rate_limit_per_min`,
   `test_positions`) можно не добавлять — без них берутся значения по умолчанию
   из кода. Их описание — в `config.sample.php`.
4. **Проверка.** Прогнать cron вручную (шаг 8) и открыть `api/health.php`:
   `"controllers_fresh": true`, `"controllers_online"` — число больше нуля,
   `"api_key": false`.
5. **У диспетчеров.** Обновить плагин, убрать из `GalaxyATMSystem.json` строку
   `"ApiKeyFile": "squawk-key.txt",` и удалить сам
   `Documents\Galaxy ATM System\squawk-key.txt`. Ключ больше нигде не нужен, и
   если он где-то утёк — это уже неважно.

Порядок важен: сервер обновляется первым. Старый плагин с новым сервером работает
(лишний заголовок с ключом просто игнорируется), новый плагин со старым сервером —
нет.

## Автодеплой с GitHub

Файл `.github/workflows/deploy-server.yml`: при каждом push в `main`, в котором
менялось что-то в `server/`, GitHub заходит на Beget по SSH, выполняет `git pull`
в `~/squawk/repo` и запускает `server/deploy.sh`, который копирует `public/` и
`lib/` в папку сайта (см. шаг 6) — сайт сразу работает на новом коде. `config.php`
деплой не трогает ни в репозитории, ни в папке сайта.

Для этого GitHub нужен свой ключ входа на Beget — отдельный от чтения репозитория,
которое теперь идёт без ключа вообще (репозиторий публичный).

### 1. Ключ для GitHub Actions (на Beget, в окне SSH)

```bash
ssh-keygen -t ed25519 -f ~/beget_actions -N "" -C github-actions
cat ~/beget_actions.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys && chmod 711 ~/.ssh
cat ~/beget_actions
```

Последняя команда выведет **приватный** ключ — несколько строк от
`-----BEGIN OPENSSH PRIVATE KEY-----` до `-----END OPENSSH PRIVATE KEY-----`.
Скопируйте их **все, включая строки BEGIN и END**.

### 2. Секреты и переменные на GitHub

Репозиторий → **Settings** → слева **Secrets and variables** → **Actions**.

Вкладка **Secrets** → **New repository secret**, три штуки:

| Name | Secret |
|---|---|
| `BEGET_HOST` | `СЕРВЕР` (имя сервера из шага 5, например `имя.beget.tech`) |
| `BEGET_USER` | `ЛОГИН` |
| `BEGET_SSH_KEY` | приватный ключ из пункта 1 целиком |

Вкладка **Variables** → **New repository variable**:

| Name | Value |
|---|---|
| `BEGET_WEB_ROOT` | **обязательно** — `ИМЯ_КОРНЯ_САЙТА` из шага 6 (например `squawk.ЛОГИН.beget.tech`), относительно домашней папки |
| `SQUAWK_HEALTH_URL` | необязательно — `http://squawk.ДОМЕН/api/health.php`, после деплоя проверит, что сервер отвечает |
| `BEGET_REPO_DIR` | необязательно — только если клон лежит не в `squawk/repo` |

### 3. Удалить ключ с сервера

После того как секрет сохранён, файл больше не нужен (вход по нему остаётся
разрешён через `authorized_keys`):

```bash
rm ~/beget_actions ~/beget_actions.pub
```

### 4. Проверить

GitHub → вкладка **Actions** → слева **«Deploy squawk server»** → справа
**Run workflow** → **Run workflow**. Через полминуты запуск должен стать зелёным;
внутри шага «Pull and sync on Beget» — последний коммит и строка
`deploy.sh: synced public/ and lib/ into ...`.

Частые ошибки в логе запуска:

| Сообщение | Что не так |
|---|---|
| `secrets are required` | не заведены секреты из пункта 2 |
| `BEGET_WEB_ROOT repository variable is required` | не задана переменная `BEGET_WEB_ROOT` из пункта 2 |
| `Permission denied (publickey)` | в `BEGET_SSH_KEY` ключ не целиком, или пункт 1 не выполнен |
| `Could not resolve hostname` | неверный `BEGET_HOST` |
| `cd: squawk/repo: No such file or directory` | клон не в `~/squawk/repo` — задайте `BEGET_REPO_DIR` |
| `web root ... does not exist` | неверный `BEGET_WEB_ROOT` — сверьте с `ls -la ~` |
| `git: command not found` | на Beget git доступен только в `ssh localhost -p222` — напишите, поправим workflow |
| `Not possible to fast-forward` | файлы в `~/squawk/repo` правили руками на сервере — там `git status`, лишние правки убрать |

Первый запуск сразу после появления workflow в репозитории упадёт с
`secrets are required` — это ожидаемо, пока не сделан пункт 2.

Автодеплой обновляет **только код**. Если когда-нибудь изменится `schema.sql`,
новую структуру базы нужно применить вручную через phpMyAdmin, а если изменятся
пароль базы или ключ API — поправить `config.php` вручную в обоих местах (шаг 7).

## Как выбирается код

1. Диапазоны позиции из `config.php` (по `.ese`): ULLI_GND — 0720–0757,
   ULLL_R/R5/R6 — 0701–0717, остальные ULLI/ULLL/ULOL — 0760–0777. Когда свои
   кончились — общий пул 0701–0777.
2. Пропускаются: коды, выданные другим бортам; коды, которые пищит или которые
   назначены любому пилоту VATSIM в радиусе 1000 км от ULLI (соседние РПИ тоже);
   0000, 1000, 1200, 2000, 7000, 7500, 7600, 7700.
3. Из свободных первым идёт код, который ни разу не выдавался, затем тот, что
   освободился раньше всех — только что освобождённый код уходит последним.

Код держится за бортом, пока пилот в сети. Когда пилота нет в данных VATSIM дольше
`release_after_min` (10 минут), код возвращается в пул. Если данные VATSIM не приходят
(сбой сети или cron), ничего не освобождается.
